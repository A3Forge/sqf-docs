## Документация (BIKI)

Не выдумывай команды, события и их параметры: в SQF нет стандартной библиотеки, кроме
команд движка и функций BIS_fnc_* / CBA. Если нет полной уверенности в синтаксисе,
возвращаемом значении, локальности (AL/AG, EL/EG), версии игры или известных проблемах —
сначала посмотри описание.

`community.bistudio.com` закрыт Cloudflare и через WebFetch/curl обычно не открывается.
Используй распарсенную BIKI в YAML — репозиторий `acemod/arma3-wiki`, ветка `dist`:

- Команда:
  `curl -s https://raw.githubusercontent.com/acemod/arma3-wiki/dist/commands/<имяКоманды>.yml`
  (например `commands/isFlatEmpty.yml`). Важные поля: `syntax` (параметры и `ret`),
  `argument_loc` / `effect_loc`, `problem_notes`, `examples`.
- Событие: `events/<группа>/<Событие>.yml`, группы — `standard`, `mission`,
  `multiplayer`, `user_interface`, `projectile`, `group`, `user_action`, `eden`, `music`.
- Функции `BIS_fnc_*` в этом репозитории не описаны — смотри их исходники в распакованных
  данных игры (`P:\a3\functions_f\...`), если они есть у пользователя, или в функции
  внутри игры (`functions viewer`).

## Основные правила

1. **Приоритет операторов**: унарные команды связывают сильнее арифметики, бинарные —
   слабее. `_arr select _i + 1` — это `_arr select (_i + 1)`;
   `count _arr - 1` — это `(count _arr) - 1`. Сомневаешься — ставь скобки.
2. **Нет short-circuit по умолчанию**: `a && b` всегда вычисляет `b`. Используй ленивую
   форму `a && {b}` / `a || {b}`, если `b` дорогое или может упасть
   (например `!isNull _x && {alive _x}`).
3. **Всегда `private`** для локальных переменных (`private _x = ...`), аргументы читай
   через `params [["_unit", objNull, [objNull]], ["_dist", 100, [0]]];`.
   Не используй `_this select N` в новом коде.
4. **Массивы — это ссылки.** `_b = _a` указывает на тот же массив; копия — `+_a`.
   `pushBack`, `append`, `set`, `deleteAt`, `sort`, `resize` меняют массив на месте.
5. **Сравнения**: `==` для строк регистронезависим и не предназначен для массивов и
   булевых значений; `isEqualTo` строгий (учитывает регистр и тип, работает с массивами).
   `in`, `find`, `findIf` со строками регистрозависимы.
6. **Знай окружение**: scheduled (`spawn`, `execVM`, init.sqf) может делать
   `sleep`/`waitUntil` и может быть прерван между любыми двумя инструкциями;
   unscheduled (event handlers, `call` из unscheduled, `preInit`, блоки `isNil {}`)
   не может приостанавливаться и выполняется атомарно. Проверка — `canSuspend`. См. scheduler.md.
7. **Локальность**: у каждой команды есть локальность аргументов (AL/AG) и эффекта (EL/EG).
   Команда с локальным аргументом на удалённом объекте молча ничего не делает.
   Выполняй её там, где объект локален: `[_veh, _fuel] remoteExec ["setFuel", _veh];`.
8. **Не доверяй клиентам.** Серверный код, вызываемый через `remoteExec`, должен
   проверять `remoteExecutedOwner`, аргументы и их типы. Не передавай по сети код для
   выполнения и не делай `call compile` строк из сети. Белый список — `CfgRemoteExec`.
9. **`player` равен `objNull`** на выделенном сервере и в начале инициализации клиента.
   Не используй `player` в серверном коде; на клиенте при необходимости
   `waitUntil {!isNull player}`.
10. **Функции — через CfgFunctions** (`TAG_fnc_name`, компилируются final), а не
    повторными `execVM` / `compile preprocessFile`. Все глобальные переменные и функции —
    с префиксом проекта (`TAG_`).
11. **Возвращаемое значение** — значение последнего выражения в блоке (ключевого слова
    `return` нет). Не заканчивай функцию присваиванием, если от неё ждут значение.
12. **`exitWith`** выходит только из текущей области видимости (из цикла или из
    родительской области `if`), а не из всей функции, если вызван во вложенном блоке.
    Используй `scopeName`/`breakOut` или перестрой код.
13. **Позиции**: используй пары `getPosASL`/`setPosASL` или `getPosATL`/`setPosATL`.
    Не смешивай форматы; `getPos`/`setPos` работают в AGL(S), медленные и неоднозначные.
14. **Числа — 32-битные float.** Целые больше 16 777 216 теряют точность; не храни в
    числах SQF большие ID, суммы денег, Steam UID (UID — только строкой).
15. **Комментарии** `//` и `/* */` вырезает только препроцессор. Код, собранный из строки
    через `compile`, не должен их содержать (или используй `compileScript` / файлы через препроцессор).
16. **Кириллица в строках**: `count`, `select`, `find` для строк по умолчанию работают
    с байтами UTF-8, а не с символами (`count "привет"` → 12). Для русского текста —
    `forceUnicode 1;` перед командой (см. syntax-pitfalls.md).
17. **`uiNamespace` и `profileNamespace` — недоверенные.** Игрок может изменить их до
    захода на сервер (`uiNamespace` переживает смену миссий, `profileNamespace` лежит
    файлом на диске). Никогда не храни там то, что потом выполняется (`call`, `spawn`,
    `compile`, `execVM`, имена функций для вызова, обработчики событий), и не бери
    оттуда ничего, что влияет на права, деньги, роли или игровой баланс. Допустимо —
    простые флаги и настройки удобства (например «игрок уже согласился с правилами»,
    громкость, последняя открытая вкладка), с проверкой типа при чтении.
    Правило — про **клиентские** машины: `uiNamespace` выделенного сервера игрок не
    контролирует, там можно хранить, например, имя протокола БД между миссиями.
    См. multiplayer.md, раздел «Данные на стороне клиента».
18. **Функции модов (CBA, ACE и др.) — только если мод точно есть в сборке.** В ванильной
    игре нет `CBA_fnc_*`, `CBA_missionTime`, `ace_*`, макросов `GVAR`/`FUNC`. Вызов
    отсутствующей функции часто не даёт явной ошибки: `call` на неопределённой переменной
    молча ничего не делает или возвращает nil, и баг ищется долго. Перед использованием убедись, что мод в зависимостях
    проекта (см. ниже); если не уверен — спроси пользователя или пиши на ванильных командах.
    Мод должен быть загружен на **той машине, где выполняется код**: если клиентский код
    приходит с server-side мода, CBA нужен и у клиентов.
19. **Время в будущем — `serverTime + задержка`.** Дедлайны, которые должны одинаково
    понимать сервер и клиенты (респаун техники, конец этапа, кулдауны), храни как
    абсолютное `serverTime + delay` и сравнивай с `serverTime`. Не используй `time`
    (на каждой машине своё) и `diag_tickTime` (только для локальных кулдаунов, не
    покидающих машину). Для дедлайнов, переживающих рестарт сервера, — реальное время
    (`systemTimeUTC` / `NOW()` в БД). См. positions-and-time.md.
20. **Никаких «магических» данных.** Числа и строки со смыслом настройки (задержки,
    радиусы, лимиты, цены, роли, классы, имена переменных/маркеров, тексты, IDD/IDC)
    не хардкодь в коде — выноси в `#define` в общий `.hpp` проекта с комментарием
    (смысл и единицы) и используй макрос. Встретил такое значение в коде, который
    правишь, — вынеси и замени все вхождения. Сначала найди существующий `.hpp` с
    макросами в проекте и следуй его стилю. См. patterns.md, раздел 6.
21. **extDB3: кавычки в тексте из БД экранируй.** Для `N-STRING` extDB3 сам не
    экранирует `"` внутри значения — пользовательский текст отдавай как
    `N-STRING-add_escape_quotes` (или `REPLACE(col, '"', '""')` в SELECT), иначе ломается
    `parseSimpleArray` всего ответа. `:` во входах ломает разбор аргументов.
    `Strip Chars` работает только для значений с опцией `strip`, `mysql_escape` — только
    без prepared statement. Подробности — extdb3.md.

## Зависимости от модов

Как понять, что мод (CBA, ACE, ...) есть в сборке:

- в `config.cpp` мода он в `requiredAddons[]` (`"cba_main"`, `"ace_main"`, ...);
- в `mission.sqm` он в `addons[]`, а миссия уже использует его функции;
- в параметрах запуска сервера (`-mod=` / `-serverMod=`), в пресете лаунчера, в описании проекта (CLAUDE.md, README);
- в проекте уже есть вызовы `CBA_fnc_*` / `ace_*` или `script_component.hpp` с макросами CBA.

Если мод необязательный — проверяй во время выполнения и делай ванильную ветку:

```sqf
TAG_hasCBA = isClass (configFile >> "CfgPatches" >> "cba_main");
TAG_hasACE = isClass (configFile >> "CfgPatches" >> "ace_main");
// или по конкретной функции: !isNil "CBA_fnc_addPerFrameHandler"
```

Ванильные замены частых функций CBA — в scheduler.md.

## Стиль кода

- Отступ 4 пробела, `{` на той же строке, одна инструкция на строку, `;` после каждой.
- Заголовок функции: автор, описание, параметры, возвращаемое значение, пример.
- Проверяй вход через `params` с массивом типов; ранний выход — `if (...) exitWith {...};`.
- Перед чтением возможно неопределённых глобальных переменных — `isNil "VAR"` / `isNil {expr}`.
- Короткие строки собирай через `format ["%1 - %2", _a, _b]`; `str` — для отладки.
- **Строку, которая может быть длинной** (JSON, `toJSON`/`str` массивов и hashmap,
  данные из БД, списки игроков/предметов, текст для `ExecJS`, логи с данными), собирай
  конкатенацией (`"a" + _b + "c"`) или `joinString`, **не `format`**: до Arma 3 2.18
  результат `format` молча обрезается до 8191 символа (с 2.18 — до 8 388 608).
  У `+` и `joinString` такого лимита нет. Много кусков или цикл — `joinString`.
- Логирование — `diag_log format ["[TAG] ...", ...]` (пишется в RPT); не спамь `hint` в MP.
- Вместо параллельных массивов или хаков с `setVariable` используй hashmap
  (`createHashMap`, `get`, `set`, `getOrDefault`).
- Не пиши на SQS. Не собирай имена переменных через `call compile format [...]` —
  используй `missionNamespace getVariable` / `setVariable` или hashmap.

## Проверка перед завершением

- [ ] Каждая локальная переменная объявлена через `private` или пришла из `params`.
- [ ] Локальность каждой команды соответствует машине, на которой выполняется код.
- [ ] `sleep`/`waitUntil` только в scheduled-коде; нет долгих циклов в unscheduled.
- [ ] Ленивые `{}` справа от `&&`/`||` где нужно; скобки вокруг арифметики рядом с `select`/`#`.
- [ ] Минимум сетевого трафика: нет `publicVariable`/`setVariable [.., true]` в быстрых циклах.
- [ ] Серверный код не использует `player`; клиентский не полагается на `isServer`.
- [ ] Event handlers не дублируются (респаун, повторная инициализация, JIP).
- [ ] Имена с префиксом проекта; глобальное пространство не засорено.
- [ ] Ничего из `uiNamespace` / `profileNamespace` не выполняется и не влияет на права/баланс.
- [ ] Каждая функция CBA/ACE/другого мода используется только если мод точно есть в сборке
      на машине, где выполняется код (или есть проверка и ванильная ветка).
- [ ] Дедлайны в MP — `serverTime + задержка`, сравнение тоже с `serverTime`.
- [ ] Нет магических чисел/строк: настройки и повторяющиеся значения — в `#define`.
