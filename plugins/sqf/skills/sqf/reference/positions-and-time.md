# Позиции, векторы, время

## Форматы позиций

| Формат | Z отсчитывается от | Получить / установить |
|---|---|---|
| ASL | уровня моря | `getPosASL` / `setPosASL` |
| ATL | поверхности земли | `getPosATL` / `setPosATL` |
| AGL | земли над сушей, поверхности моря (с волнами) над водой | `ASLToAGL`, многие команды принимают AGL |
| AGLS | как AGL, но над дорогами/полами зданий | `getPos` / `setPos` |
| ASLW | поверхности моря с учётом волн | `getPosASLW` / `setPosASLW` |
| World | центра модели, а не точки касания земли | `getPosWorld` / `setPosWorld` (самые быстрые, точные) |

- Выбирай один формат на участок кода и конвертируй явно: `ASLToATL`, `ATLToASL`,
  `ASLToAGL`, `AGLToASL`.
- `getPos`/`setPos` медленные, и их смысл зависит от того, что под объектом — не используй в новом коде.
- Размещение объекта на другом объекте / полу здания: считай в ASL
  (`lineIntersectsSurfaces` возвращает ASL).
- `modelToWorld` возвращает AGL; `modelToWorldWorld` — world (на основе ASL).
  `worldToModel` принимает AGL; `worldToModelVisual` — для позиций в момент отрисовки.
- `*Visual`-варианты (`getPosASLVisual`, `modelToWorldVisual`) — для отрисовки/UI каждый кадр;
  для логики симуляции используй обычные.
- Многие команды принимают 2D-позиции `[x, y]`; `distance` с 2D-позициями считает z = 0.

## Направление и векторы

- `getDir`/`setDir` (градусы, 0 = север, по часовой). `setDir` перед `setPos`;
  для полной ориентации — `setVectorDirAndUp [_dir, _up]`.
- `_a getDir _b` / `_a getRelDir _b`.
- Векторные команды: `vectorAdd`, `vectorDiff`, `vectorMultiply`, `vectorNormalized`,
  `vectorMagnitude`, `vectorDotProduct`, `vectorCrossProduct`, `vectorDistance`,
  `vectorFromTo`.
- `_pos getPos [_distance, _heading]` — позиция относительно другой (AGL); удобно для смещений.

## Время

| Значение | Смысл |
|---|---|
| `time` | секунды с начала миссии; **на каждой машине своё**; стоит на паузе |
| `serverTime` | секунды с (пере)запуска сервера; синхронизируется со всеми клиентами при старте миссии, при подключении JIP и каждые 5 минут. На сервере отличается от `time` и `diag_tickTime` |
| `CBA_missionTime` | синхронизированное время миссии (только если CBA есть в сборке) |
| `diag_tickTime` | реальное время с запуска игры **на этой машине**; на разных машинах разное |
| `systemTimeUTC` / `systemTime` | реальная дата и время ОС |
| `daytime` / `date` | внутриигровые часы |

- `sleep` масштабируется `accTime`; `uiSleep` — нет.
- Точность: float-время теряет точность при долгом аптайме сервера; сравнивай разницы,
  а не точное равенство.

### Отложенные события и дедлайны: `serverTime + задержка`

Если нужно надёжно запомнить момент в будущем, который должны одинаково понимать сервер
и клиенты (респаун техники, конец разминки, кулдаун способности, окончание голосования),
храни **абсолютный дедлайн** `serverTime + задержка` и сравнивай с `serverTime`:

```sqf
// script_macros.hpp: #define VEHICLE_RESPAWN_DELAY 300   // через сколько восстанавливать технику, с

// Сервер: техника уничтожена — запомнить, когда её восстановить
_veh setVariable ["TAG_respawnAt", serverTime + VEHICLE_RESPAWN_DELAY, true];   // рассылка: клиенты покажут таймер

// Сервер: менеджер-цикл проверяет дедлайны
if (serverTime >= (_veh getVariable ["TAG_respawnAt", 1e10])) then { /* респаун */ };

// Клиент: обратный отсчёт в UI — та же шкала времени
private _left = ((_veh getVariable ["TAG_respawnAt", serverTime]) - serverTime) max 0;
```

Почему не другие варианты:
- `time` — у каждой машины своё (JIP-клиент начинает отсчёт с момента захода),
  дедлайн с сервера на клиенте будет показывать неправильное время.
- `diag_tickTime` — время работы игры на конкретной машине. Годится **только** для
  локальных кулдаунов, которые не покидают машину (например, антиспам на сервере в
  `setVariable` без рассылки), но не для значений, которые отправляются клиентам.
- «Осталось N секунд» вместо дедлайна — значение устаревает сразу после отправки
  и требует постоянной пересылки. Дедлайн отправляется один раз.
- Только `sleep VEHICLE_RESPAWN_DELAY` в spawn-скрипте — scheduled-код может опоздать под нагрузкой, а
  скрипт может умереть с ошибкой; состояние нигде не сохранено. Храни дедлайн и проверяй
  его в одном менеджер-цикле.
- Не смешивай шкалы: дедлайн из `serverTime` сравнивай только с `serverTime`.

Ограничения `serverTime`:
- Отсчёт идёт с перезапуска сервера: для дедлайнов, которые должны пережить рестарт
  (баны, ежедневные награды, записи в БД), используй реальное время — `systemTimeUTC`
  на сервере или `NOW()` в базе данных.
- В одиночной игре / редакторе до v2.18 `serverTime` возвращает 0 (с 2.18 — как
  `diag_tickTime`). Для тестов в SP учитывай это или подставляй `time`.

## Случайность

- `random 10` → float `[0, 10)`; целое: `floor random 10`.
- `selectRandom _arr`, `selectRandomWeighted [a, вес, b, вес]`.
- `random [min, mid, max]` — распределение, близкое к нормальному.
- Случайные значения разные на каждой машине; если всем клиентам нужно одно и то же —
  генерируй на сервере и рассылай.
