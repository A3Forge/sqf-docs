# Управление игрой из SQF: меню, редактор, миссии

Как из SQF ходить по интерфейсу игры: нажимать кнопки меню, открывать редактор и миссии,
запускать превью и сценарии, выходить из миссии и из игры. Пригодится, когда код
выполняется в запущенной игре — из debug console, скриптов мода или агентом через MCP
(раздел [Через MCP](#через-mcp-sqf-mcp) в конце).

Проверено на Arma 3 2.23.

## Где выполняется код и что доступно

| Где | Как узнать | Что есть |
|---|---|---|
| Главное меню и другие меню | нет `findDisplay 46`, `!is3DEN` | интерфейс (`findDisplay`, `ctrlActivate`, `createDialog`), конфиги, `uiNamespace`/`profileNamespace`, `playMission`. Мира и юнитов нет, `player` = `objNull` |
| Редактор Eden | `is3DEN` | всё из меню плюс команды Eden: `create3DENEntity`, `set3DENAttributes`, `get3DENSelected`, `all3DENEntities`, `load3DENScenario`, `do3DENAction` |
| Превью из редактора | `is3DENPreview` | обычная миссия, см. [testing.md](testing.md) |
| Миссия | `!isNull findDisplay 46` | обычная миссия |

- Во время загрузки код не выполняется.
- В меню и редакторе `missionNamespace` есть, но его переменные пропадут при старте
  следующей миссии.
- При завершении любой миссии (в т.ч. выходе из превью и из редактора) движок снимает
  все scheduled-скрипты, даже запущенные из `uiNamespace`.
- `preInit`-функции CfgFunctions в самом редакторе (без превью) не вызываются; при
  запуске игры до меню работает `preStart`.

## Как понять, что на экране

- `allDisplays` — открытые дисплеи. **Порядок не равен «кто сверху»**: при открытом
  меню паузы последней может идти карта (12), а не меню (49). Нужный дисплей ищи по IDD
  через `findDisplay`.
- `allDisplays select -1` падает с ошибкой, если дисплеев нет. Проверяй `count`.
- Кнопки и тексты дисплея:
  ```sqf
  (allControls findDisplay 49 select {ctrlShown _x && {ctrlText _x != ""}})
      apply {[ctrlIDC _x, ctrlClassName _x, ctrlText _x, ctrlEnabled _x]}
  ```
  Тексты — на языке игры; опирайся на `ctrlIDC` и `ctrlClassName`, а не на текст.
- **Модальные окна сообщений (`RscMsgBox`, IDD 228) не видны ни в `allDisplays`, ни
  через `findDisplay 228`.** Пока такое окно открыто, игра стоит на паузе
  (`isGamePaused`), а `closeDisplay` других дисплеев и `endMission` не срабатывают.
  Скрипты интерфейса регистрируют дисплеи в `uiNamespace` под именем класса
  (`BIS_fnc_initDisplay`) — так окно и находится:
  ```sqf
  private _box = uiNamespace getVariable ["RscMsgBox", displayNull];
  // текст — _box displayCtrl 101; кнопки: 1 — «Да/ОК», 2 — «Нет/Отмена»
  ctrlActivate (_box displayCtrl 1);
  ```
  Все зарегистрированные так дисплеи с именами классов:
  ```sqf
  (uiNamespace getVariable ["GUI_displays", []])
      apply {[ctrlIDD _x, _x getVariable ["BIS_fnc_initDisplay_configClass", ""]]}
  ```

## Управление интерфейсом

- Кнопка — `ctrlActivate (_display displayCtrl IDC)`. Срабатывает и у кнопок, скрытых в
  свёрнутых разделах главного меню.
- Список — `lbSetCurSel`, данные элемента — `lbData`/`lbText`. Поле ввода — `ctrlSetText`.
- Закрыть диалог — `_display closeDisplay 2` (как «Отмена»).
- **Не закрывай дисплей 0** (главное меню): игра не выйдет, а останется без интерфейса и
  без кнопки выхода.
- Действие, которое открывает следующий экран, проверяй следующим вызовом: новый
  дисплей появляется не в том же кадре.

## Главное меню (IDD 0)

| idc | Кнопка |
|---|---|
| 142 | Редактор → выбор острова (IDD 51) |
| 105 | Браузер серверов (IDD 8; «Назад» — idc 2, «Хост-сервер» — 167) |
| 106 | **Выход из игры** — сразу, без подтверждения |
| 101, 103, 150, 151 | Кампании, сценарии, демонстрации, испытания |
| 154, 206 | Быстрая игра, Протокол Apex |
| 149, 152, 203, 143 | Учебный лагерь, VR-обучение, Виртуальный арсенал, Боевой устав |
| 301, 302, 303, 307 | Настройки: видео, звук, управление, игра |
| 140, 12701 | Дополнения, настройки дополнений (CBA) |

Проверены 142, 105, 106; остальные idc взяты из дампа меню.

## Редактор

### Открыть редактор с пустым сценарием

```sqf
ctrlActivate ((findDisplay 0) displayCtrl 142);     // → выбор острова, IDD 51
```

Следующим вызовом, когда открыт IDD 51:

```sqf
private _d = findDisplay 51;
private _list = _d displayCtrl 101;                 // lbData — имя мира: "Altis", "VR", ...
for "_i" from 0 to (lbSize _list - 1) do {
    if (_list lbData _i == "VR") exitWith {_list lbSetCurSel _i};
};
ctrlActivate (_d displayCtrl 1);                    // «Далее» → загрузка Eden
```

Готовность — `is3DEN` (VR грузится за секунды, большие острова дольше).

### Открыть существующую миссию

```sqf
load3DENScenario "missions\Frontline.VR";      // SP-миссия профиля
load3DENScenario "mpmissions\MyMP.Altis";      // MP-миссия профиля
load3DENScenario "VR";                          // новый пустой сценарий на острове
```

- Работает **только в редакторе**. Из главного меню возвращает `false` и ничего не делает:
  сначала открой редактор, потом загружай.
- Путь — относительно папки профиля, **с префиксом `missions\` или `mpmissions\`**. Без
  него (`"Frontline.VR"`, как в примере BIKI) — ошибка «Invalid scenario name format».
- Возвращает `true` сразу, миссия догружается за пару секунд: проверь `missionName`,
  `getMissionPath ""`, `all3DENEntities`.
- Сохранить — `do3DENAction "MissionSave"` (в текущую папку миссии).

### Превью

```sqf
do3DENAction "MissionPreview";
```

- Нужен юнит игрока. В новом сценарии:
  ```sqf
  private _u = create3DENEntity ["Object", "B_Soldier_F", [1000, 1000, 0]];
  set3DENAttributes [[[_u], "ControlSP", true]];
  ```
- **Eden сохраняет миссию перед превью** (уведомление «Сценарий сохранён»). Чужую миссию,
  открытую «только посмотреть», превью перезапишет текущим состоянием редактора.
- Готовность — `is3DENPreview && {!isNull player}`.
- Возврат в редактор — `endMission "END1"`. Если в миссии `debriefing = 0` — сразу в
  редактор, иначе дебрифинг (IDD 50) → `ctrlActivate ((findDisplay 50) displayCtrl 1)`.
- Доступность экшена — `get3DENActionState "<action>"` (-1 — недоступен). MP-превью
  (`"MissionPreviewMP"`) в обычном редакторе недоступно: только в редакторе, открытом из
  «Хост-сервер», где `is3DENMultiplayer` = `true`.

### Из редактора в главное меню

```sqf
(findDisplay 313) closeDisplay 2;
```

`do3DENAction "3DENExit"` из скрипта ничего не делает. Для несохранённого нового
сценария окна «сохранить изменения?» не было.

## Сценарии и миссии

### Запустить сценарий из главного меню

```sqf
playMission ["", "\a3\missions_f\showcases\Showcase_Infantry.Stratis", true];
// 1-й параметр — кампания ("" — одиночный сценарий), 3-й — пропустить интро и брифинг
```

- Путь — каталог миссии внутри PBO. Классы сценариев: `configFile >> "CfgMissions"`
  (`Missions`, `MPMissions`, `Showcases`, ...).
- Готовность — `!isNull findDisplay 46 && {time > 0}`.
- Некоторые сценарии ведут себя по-своему: например, `Arsenal.VR` сразу открывает Арсенал
  (дисплей с IDD -1), а закрытие Арсенала завершает сценарий.

### Выйти из миссии в главное меню

Основной путь — `endMission "END1"` → дебрифинг (IDD 50) → «Далее»:

```sqf
endMission "END1";
// следующим вызовом:
ctrlActivate ((findDisplay 50) displayCtrl 1);
```

Через меню паузы:

```sqf
(findDisplay 46) createDisplay "RscDisplayInterrupt";            // IDD 49
ctrlActivate ((findDisplay 49) displayCtrl 104);                 // «Выйти» («Отмена»)
// в одиночной игре — подтверждение RscMsgBox («Все сохранения будут потеряны»):
ctrlActivate ((uiNamespace getVariable "RscMsgBox") displayCtrl 1);
// → дебрифинг IDD 50 → ctrlActivate ((findDisplay 50) displayCtrl 1)
```

Прочие кнопки меню паузы (IDD 49): 2 — продолжить, 101 — настройки, 119 — загрузить,
1003 — заново.

## Выход из игры

```sqf
ctrlActivate ((findDisplay 0) displayCtrl 106);
```

Только из главного меню: сначала выйди из миссии и из редактора. Игра закрывается сразу и
штатно («Shutdown normally» в RPT).

## Ожидание

- Переход (загрузка мира, открытие дисплея) проверяй отдельным вызовом после действия,
  а не в том же коде. Прежде чем ждать, проверь результат самой команды: `false` от
  `load3DENScenario` значит, что ждать нечего.
- Внутри игры ждать можно только в scheduled-коде. В меню и на паузе работает `uiSleep`;
  `sleep` на паузе стоит.

## Через MCP (sqf-mcp)

Мод [sqf-mcp](https://github.com/A3Forge/sqf-mcp) поднимает MCP-сервер внутри игры.
С версии 0.2.0 код выполняется везде, где описано выше: в меню, в редакторе, в превью и в
миссии (раньше — только в миссии).

| MCP-сервер | Порт | Машина |
|---|---|---|
| `arma-client` | 8771 | клиент: одиночная игра, превью, хост MP, меню, редактор |
| `arma-server` | 8770 | выделенный сервер |
| headless | 8772 | headless-клиент |

- Инструменты: `execute_sqf` и `screenshot` (только клиент). Снимок делай после
  выполнения кода — так видно результат.
- MCP поднимается при запуске игры, до главного меню. Claude Code подключается к MCP при
  старте сессии: если игру запустили позже, переподключись (`/mcp`). Без этого MCP можно
  вызвать по HTTP: `POST http://127.0.0.1:8771/mcp`, JSON-RPC `tools/call`.
- Игра запускается без BattlEye и с модом `@sqf_mcp` в `-mod=`.
- **Вызовы держи короткими**: одно действие → отдельная проверка состояния. Длинное
  ожидание в одном вызове выглядит как зависание, а при молча не сработавшей команде
  ждёт впустую.

### execute_sqf

- По умолчанию **unscheduled** (атомарно, без `sleep`/`waitUntil`). `scheduled: true` —
  через `spawn`; тогда увеличь `timeout_seconds`.
- Результат — значение последнего выражения: `STRING` как есть, остальное через `str`;
  без значения — `type: "NOTHING"`.
- Комментарии `//` и `/* */` можно; `#define`/`#include` нельзя.
- Локальные — через `private`. Глобальные попадают в `missionNamespace` текущего контекста.
- `throw` → `ok: false`, `error` = исключение. Ошибка движка → `ok: false`, «выполнение
  прервано ошибкой скрипта», текст — в `rpt`.
- `rpt` — все строки RPT за время выполнения, не только твои: ошибки ванильных
  сценариев, ассерты diag-сборки. Свои ищи по `Error in expression <твой код>`.
- `ok: true`, но ничего не произошло — команда могла молча не сработать (`call` от
  неопределённой переменной возвращает nil без ошибки; часть команд работает только в
  своём контексте). Проверь состояние отдельным вызовом.

Поля ответа:

| Поле | Смысл |
|---|---|
| `context` | `menu` (главное меню, любые меню, дебрифинг обычной миссии), `eden`, `preview` (превью и его дебрифинг), `mission` |
| `displays` | IDD из `allDisplays` (без `RscMsgBox`) |
| `mission`, `world` | `missionName`, `worldName` (в меню могут остаться от прошлой миссии) |

### Диагностика

- «Игра не забрала задание за 5s» — идёт загрузка, открыто модальное окно
  (`RscMsgBox`) или игра висит. Подожди и повтори, сделай `screenshot`.
- В RPT мод пишет `[sqf_mcp] MCP (client) listening on ...` при запуске и
  `[sqf_mcp] pump started: ...` при каждом (пере)запуске опроса заданий — в меню, в
  редакторе, в миссии. Нет этих строк — мод не загружен (BattlEye, не тот `-mod=`).
